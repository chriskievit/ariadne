01/P3 · P6 · P12 in the header and list

The list, driven from the keyboard

The header search field is gone — replaced by a compact ⌘K affordance, which frees the space the sync readout needs in Phase 3. A query bar sits above the list where slicing actually happens. Row three has focus.

  1. 1The focused row is marked by shape and colour. A 2px leading bar plus a ring — so it survives greyscale and colour-blindness, and its primary action reveals its binding.
  2. 2Query and chips are one state. Clicking the Azure DevOps chip wrote source:ado; editing the text lights the chip. Two views, one source of truth.
  3. 3Saved views are chips with optional shortcuts. Unlimited, because the store is a local file — GitHub's 15-filter cap exists to protect someone else's infrastructure.
  4. 4An empty group states itself in one muted line and says why it's empty — "0 matching this query", not a blank card.
  5. 5A woken snooze is labelled. "woke early" in the context line, so the item reappearing never looks like a bug.
  6. 6Every triage action is a toast with 10 seconds of undo. The verb in the toast is the verb on the control.

02/P3 · the discoverability contract

Everything the keyboard does, on one screen

Keyboard-first design's documented failure is that new users never find the functionality. The answer is ?, generated from lib/keymap.ts — the single place a binding may be declared, so the sheet cannot drift from the app.

03/P5 · the invariant under most pressure

Three local verbs, and the sentence that has to be on screen

Star, snooze, done. None of them produces a request to GitHub or Azure DevOps. This is the task most likely to drift across INV-2 — "while we're here, mute it upstream" is exactly what Octobox chose — so the reassurance is not buried in a help page. It is in the menu the action lives in.

Decision · snooze predictability §12 question 4 asks whether a snoozed item should return early on new upstream activity. Yes — but the unpredictability is the thing to design, not the behaviour. "Until there's activity" appears as an explicit option so the mechanism is named before it fires, and the returning row carries woke early. A snooze that quietly breaks its own promise is a bug; one that tells you why it broke it is a feature.
Guard test, not a code comment A mock provider client that throws on any non-GET, exercised across start, complete, pause, star, snooze, done, plan and wrap-up. Plus a CI grep that fails on a non-GET method string in github-client.ts or ado-client.ts. The claim on the README is only true if something breaks when it stops being true.

05/P12 · the local-data advantage, stated

⌘K over an in-process file

Linear's palette feels instant because it searches a local object pool. Ariadne's pool is the database — same process, no network, no cache layer to invalidate. Five categories, closed. Every entry shows its binding, which is how the shortcuts get learned without anyone reading the help sheet.

Worth saying out loud That footer line — "19 signals searched locally · no network" — costs one <span> and is the only place in the product where the local-first architecture becomes something the user can feel rather than read about. Keep it.
