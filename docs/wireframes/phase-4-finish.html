02/P11 · the artefact nobody else can publish

The whole formula, on one screen

Reached from every breakdown popover. Generated from the same tables lib/scoring.ts scores with, so it cannot lie. Lives in a modal, not a route.

Decision · disclose the sort rules, not just the points The proposal's reference covers the point table. It has to cover more than that: sortByUrgency() promotes every in-progress item above every other item regardless of score. That rule is invisible, it overrides the number the user is being shown, and leaving it out of the reference would make the page technically accurate and practically a lie. Same for the ad-hoc threshold exemption. If a rule changes what you see, it belongs on this screen.

03/P11 · nothing, and broken

The states nobody designs

Three empty states and one first run. Each says what is absent, then offers the next action — no confetti, no apology, no shrug.

The rate-limit copy gives a clock time rather than a countdown, and says what refreshing early will do. An error that only says "try again later" makes the user run the experiment themselves.

04/P10 items 6–9 · the responsive floor

Down to 375px

The full-width list from Phase 1 degrades on its own — which is the quiet dividend of deleting the two-column layout. Below 900px the only real decisions are what leaves the row and where it goes.

  1. 1The row wraps rather than sheds. Score, title, source, context, badge and both actions all survive — they restack. Nothing becomes unreachable by pointer, which is Linear's documented failure mode and the reason keyboard parity is not enough.
  2. 2Titles wrap to two lines before they truncate, and carry the full string in title plus the accessible name when they do.
  3. 3Touch targets go to 44px in comfortable density — the primary action, the ⋯ menu, the filter chips, and the Plan the day button.
  4. 4The sync readout survives the narrowest layout. It is the one element that must never be the thing that gets dropped for space.

The gate that outranks the checkboxes Before merging any phase, one question: does this change make the user's own decision easier, or does it make a decision for them? The second answer is a blocker regardless of how good the feature is — and it is the only test in this document that cannot be automated.
