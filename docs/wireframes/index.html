Baseline/what ships today

Where the dashboard is now

Redrawn from the current build so every later phase has something exact to diverge from. Three problems are marked; each one anchors a phase.

  1. AThe thesis is invisible. Urgency arrives as an unlabelled dot. The breakdown exists in scoreBreakdown() and reaches the user only as a hover title on that dot.
  2. BThe organising principle fights the promise. Source is the container, so a Draft PR sits above a Blocked work item, the GitHub card stretches to ~190px of dead space, and titles clip at roughly 30 characters while full-width rows above them show 90.
  3. CThe day has no shape. Today is empty behind a text link while seven items are simultaneously started — three in progress, four paused.
  4. DColour does three jobs at once. Indigo means interactive, status and urgency — TIER_DOT_CLASS.medium is literally bg-primary, the same token as the Refresh button. Meanwhile Blocked is the calmest thing on screen, because adoStatusVariant() has no case for it and falls through to outline.
  5. ERefresh is the loudest element on the page. Maintenance outranks work.

The ladder/five phases, each shippable alone

What each phase buys

Dependency order from the proposal, unchanged. Every phase is a state the dashboard can live in indefinitely — no phase leaves the product half-converted.

Scope note Issue #15 calls this a polish pass, not a redesign — but its own guardrails point at P2, which deletes the source-column layout outright. That is the one place these wireframes knowingly exceed the issue: the guardrails say keep one row grammar, keep Parked dimmed inside In progress, keep Today and In progress disjoint, keep the sprint header ambient. All four survive here. What does not survive is source as container, and that was never in the guardrails.

Decisions/proposal §12, answered

Nine open questions, closed

The proposal left these for the maintainer. Each is answered here so the wireframes are drawable; each is a decision you can reverse, not an assumption buried in markup.

QuestionAnswer used in these wireframes
1 · Score bands Already derivable. Max achievable is 105 (approved_unmerged 45 + due 25 + unresolved 20 + stale 15). getPriorityTier() already draws lines at 60 / 40 / 25, and NEEDS_ATTENTION_THRESHOLD is 25 — so the four bands are ≥60 critical, 40–59 high, 25–39 medium, <25 low. No new numbers invented; the chip inherits the tier that already sorts the list.
2 · Group precedence Yes, Blocked outranks Waiting on you — the verb differs, nudge vs work. But see the deviation on the Phase 1 page: approved_unmerged is not "moving without you".
3 · Ad-hoc placement Already solved, in code, invisibly. getGroupedItems() exempts source === 'adhoc' from the 25-point threshold, so a 10-point ad-hoc item never sinks out of Needs attention. Keep the exemption, keep the shared formula, and make the exemption visible — an ad-hoc row below the threshold carries a Kept visible marker so the user can see a rule was applied. A privileged always-visible group would mean ranking by origin, the exact thing P2 deletes.
4 · Snooze on activity Yes, returns early — but says so. The snooze menu reads "until activity" as an explicit option and the row carries a Woke early marker, so the surprise is labelled rather than silent.
5 · Default capacity 6h, pre-filled and editable inline in step 4 of the first ritual. Asking on first run is a question with no context behind it; showing the arithmetic gives the answer context.
6 · Sprint denominator Sprint counters count sprint items only, and the status line says so: "0/17 sprint items done". Non-sprint signals carry no sprint mark, and the header's attention count is labelled with its own denominator rather than sharing one.
7 · Density default Comfortable (44px). Compact is one toggle away and drawn on the Phase 0 page. A tool opened dozens of times a day should not start at its tightest setting.
8 · Token storage Out of scope for a UI pass, and the README already states the .env-grade tradeoff. Phase 4 surfaces that sentence in Settings instead of hiding it.
9 · Is P6 too much surface? Inside, but only at the exact grammar listed — nine prefixes, comma OR, leading - negation. It replaces a search box that already exists; it adds no route and no dependency. The cap is the grammar, and the grammar is closed.
